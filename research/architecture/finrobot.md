## 5. THE TOOLKIT REGISTRATION MECHANISM — Tool Enablement

### Function-Level Registration

**File**: finrobot/toolkits.py:22–51 (QUOTED VERBATIM):
```python
def register_toolkits(
    config: List[dict | Callable | type],
    caller: ConversableAgent,
    executor: ConversableAgent,
    **kwargs
):
    """Register tools from a configuration list."""

    for tool in config:

        if isinstance(tool, type):
            register_tookits_from_cls(caller, executor, tool, **kwargs)
            continue

        tool_dict = {"function": tool} if callable(tool) else tool
        if "function" not in tool_dict or not callable(tool_dict["function"]):
            raise ValueError(
                "Function not found in tool configuration or not callable."
            )

        tool_function = tool_dict["function"]
        name = tool_dict.get("name", tool_function.__name__)
        description = tool_dict.get("description", tool_function.__doc__)
        register_function(
            stringify_output(tool_function),
            caller=caller,
            executor=executor,
            name=name,
            description=description,
        )
```

**Key mechanism**: `register_function` from autogen (line 45). Each function is wrapped with `stringify_output` (lines 10–19) to convert DataFrame results to strings before returning to the agent.

### Class-Level Registration

**File**: finrobot/toolkits.py:85–106:
```python
def register_tookits_from_cls(
    caller: ConversableAgent,
    executor: ConversableAgent,
    cls: type,
    include_private: bool = False,
):
    """Register all methods of a class as tools."""
    if include_private:
        funcs = [
            func
            for func in dir(cls)
            if callable(getattr(cls, func)) and not func.startswith("__")
        ]
    else:
        funcs = [
            func
            for func in dir(cls)
            if callable(getattr(cls, func))
            and not func.startswith("__")
            and not func.startswith("_")
        ]
    register_toolkits([getattr(cls, func) for func in funcs], caller, executor)
```

When a toolkit is a class (e.g., `ReportLabUtils` from agent_library.py:77), all public methods become tools.

   - 10-K, 10-Q, 8-K filings
   - HTML/PDF parsing via marker_sec_src/

5. **FinNLP / NewsAggregator**: finnlp_utils.py
   - News and sentiment data

6. **Adanos**: retail_sentiment_client.py (modern stack)
   - Retail sentiment insights

7. **Reddit**: reddit_utils.py
   - Community sentiment

### PIT Handling

**No explicit PIT (Point-in-Time) tags or timestamps in code**. Issues:

- **API call date**: FMP returns `date` field (income_df.sort_values('date') in financial_data_processor.py:42), but no recording of when the data was fetched
- **Historical data**: Comes with actual filing dates (e.g., income statement line item date = report date), so PIT is implicit in the data's year/quarter
- **Forecast data**: Explicitly labeled 2025E, 2026E, 2027E, so forward-looking data is separated from actual
- **News data**: Includes publishedDate field (agent_manager.py:60)

**Look-ahead risk**: LOW, because:
- Reports are fetched by ticker and period (past only), not by future date
- Forecasts are explicitly marked "E" (estimated)
- Backtesting uses historical OHLCV (yfinance) with date range specified upfront (quantitative.py:100–101: `yf.download(ticker_symbol, start_date, end_date)`)

**Verdict on PIT**: ASSERTED (not fully verified in backtest code). Backtesting appears to respect date boundaries, but no explicit PIT tag on every computation. ARGUS must add PIT checks if using FinRobot's data layer.

## 12. Verdict — What ARGUS Takes and What It Must Build

### What ARGUS Adopts from FinRobot

1. **Agent library and orchestration pattern** (agent_library.py + agent_manager.py)
   - Multiple agents with well-defined roles (research, risk assessment, execution validation)
   - Clean config-dict-based agent registration
   - Sequential or parallel execution of agents to generate decision signals

2. **Deterministic/narration separation** (financial_data_processor.py pattern)
   - Compute portfolio metrics (unrealized PnL, Sharpe, drawdown) in pure Python
   - Use agents only to explain risk, justify position sizing, critique trade candidates
   - Full provenance: every number comes from code, not LLM hallucination

3. **Tool registration pattern** (toolkits.py)
   - Risk-gate functions (validate position size, check portfolio correlation, enforce stop losses) as tools on a RiskAgent
   - Class-level registration for large tool sets
   - StringifyOutput wrapper for complex return types

4. **Toolkit examples** (functional/*):
   - charting.py pattern for real-time portfolio visualization
   - analyzer.py pattern for decision support narratives

5. **Multi-source data integration** (data_source/*)
   - Wrap Bitget APIs alongside external sources (FMP, Finnhub)
   - Unified financial metric extraction

### What ARGUS Must Build (Not in FinRobot)

1. **Execution Layer**
   - OrderPlacementAgent: Takes a trade signal from ResearchAgent, formats it, submits via Bitget API
   - ExecutionValidator: Confirms order receipt, tracks fills, updates portfolio state
   - OrderCancelAgent: Monitors for safety violations; cancels orders or closes positions

2. **Portfolio State Manager**
   - Current holdings, entry prices, unrealized PnL
   - Persistent across sessions (database or local state file)
   - PIT-tagged snapshots for backtest reproducibility

3. **Risk Control Framework**
   - Hard position limits (max 5% per ticker, max 20% in one sector)
   - Portfolio-level drawdown limits (liquidate if down >10%)
   - Correlation checks (disallow adding correlated positions)
   - Slippage & fee modeling (crypto-specific: maker/taker, withdrawal fees)

4. **Adaptive Agent Routing** (contextual bandit, if ARGUS wins via multi-agent consensus)
   - Track agent performance: accuracy of trade recommendations, consistency with risk gates
   - Use UCB or Thompson sampling to route new tasks to high-performing agents
   - Update policy on feedback (Did the trade hit its target? Was drawdown under limit?)

5. **Live Market Data**
   - Replace yfinance with WebSocket feeds (Bitget or Binance testnet)
   - Tick-by-tick order book for slippage estimation
   - Real-time portfolio Greeks (if options trading is included)

6. **Backtesting Harness**
   - Replace Backtrader (designed for stock backtests, has crypto gaps)
   - Bitget-compatible simulated exchange (order matching, slippage, fees)
   - Walk-forward validation with expanding training windows
   - Out-of-sample testing across market regimes (bull, bear, chop)

7. **Decision Consensus & Debate**
   - (Optional) Bull-vs-bear agents give opposing signals; judge agent decides
   - Majority vote among multiple independent trading agents
   - Confidence threshold (only trade if >2/3 agents agree)

8. **Logging & Audit Trail**
   - Every trade: agent decision reason, risk checks passed, execution details, fill price vs. target
   - Enable post-mortem analysis of failures
   - Cryptographic signature (Ed25519) on trade decisions for regulatory compliance
