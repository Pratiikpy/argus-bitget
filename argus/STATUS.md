## What is blocked on credentials only you can create

**Bitget demo-environment order placement.** The signed path is built and unit-tested; a venue has
never accepted one of our signatures because we have no key to sign with.

1. Create an API key at https://www.bitget.com/account/newapi
   — permissions Read + Trade, **Withdraw off**; enable Demo Trading on the account first.
2. `cp .secrets/bitget.env.example .secrets/bitget.env` and fill in three values.
3. `set -a && . .secrets/bitget.env && set +a`
4. `cd argus && python -m argus.execution.preflight --order`

Five ordered checks, each naming its own cause: credentials -> venue reachable -> demo routing ->
**signature accepted** -> order placed, read back, reconciled. Step 4 is the one that unit tests
cannot establish, because a signature is only correct when a venue says so.

Variable names are Bitget's own (`agent-sdk/src/config.ts:192-194`): `BITGET_API_KEY`,
`BITGET_SECRET_KEY`, `BITGET_PASSPHRASE`.
